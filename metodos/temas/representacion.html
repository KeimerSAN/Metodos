Representación de números en el computador

Bits, binario y el estándar IEEE 754: cómo cabe un número real en una palabra de 64 bits y qué se pierde en el camino.

En esta página

Practicar este tema Ver los 16 temas

Idea central

El computador no almacena números: almacena bits. Cualquier cantidad debe caber en una palabra de longitud fija (32 o 64 bits), y esa restricción es la fuente de casi todos los errores numéricos que veremos en el curso. Entender cómo se guarda un número es entender por qué 0.1 + 0.2 no da exactamente 0.3.

Sistemas de numeración

Un número en base b se escribe como una suma de potencias de b. En base 2 solo existen los dígitos 0 y 1:

Número binario entero

(dn…d1d0)2 = Σ di · 2i

Parte fraccionaria

0.d1d2… = Σ di · 2−i

Fila clave: 0.1 en decimal es periódico infinito en binario. Por eso el computador nunca guarda exactamente 0.1.

Conversión decimal → binario

  1. Parte entera: dividir repetidamente entre 2 y anotar los residuos; se leen de abajo hacia arriba.
  2. Parte fraccionaria: multiplicar repetidamente por 2 y anotar la parte entera de cada producto; se leen de arriba hacia abajo.
  3. El proceso de la parte fraccionaria puede no terminar nunca: ahí nace el error de representación.

Ejercicio resuelto: convertir 13.375 a binario

Parte entera (13): 13÷2 = 6 residuo 1; 6÷2 = 3 residuo 0; 3÷2 = 1 residuo 1; 1÷2 = 0 residuo 1. Leyendo hacia arriba: 1101.

Resultado: 13.37510 = 1101.0112. Aquí sí termina porque 0.375 = 3/8 es una fracción con denominador potencia de 2.

El estándar IEEE 754

Es la norma que usan prácticamente todos los procesadores. Un número real se guarda en tres campos: signo, exponente (con sesgo) y mantisa o significando.

Forma normalizada

x = (−1)s × 1.m × 2e−sesgo

FormatoBits totalesSignoExponenteMantisaCifras decimales útiles
Simple precisión (float)3218 (sesgo 127)23≈ 7
Doble precisión (double)64111 (sesgo 1023)52≈ 15–16

Python usa doble precisión para todos sus float: unas 15 a 16 cifras decimales significativas.

Enteros con signo: complemento a dos

Los enteros negativos no guardan un bit de signo aparte, sino que se representan en complemento a dos: se invierten todos los bits del valor absoluto y se suma 1. Con 8 bits el rango va de −128 a 127, y sumar 1 a 127 produce −128: eso es el desbordamiento (overflow).

Errores comunes

  • Suponer que todo decimal corto se guarda exacto. 0.1, 0.2 y 0.3 son periódicos en binario; solo las fracciones con denominador potencia de 2 son exactas.
  • Ignorar el desbordamiento de enteros. En lenguajes de tamaño fijo, superar el rango no genera error: produce silenciosamente un valor negativo.
  • Usar float donde hace falta double. Con 7 cifras significativas, un método iterativo puede estancarse antes de alcanzar la tolerancia pedida.

Banco de ejercicios propuestos

Conversiones a mano: el objetivo es ver dónde aparece el error de representación.

1. Convierte 45 a binario.¿Ver ejercicio resuelto?

45÷2 = 22 residuo 1

22÷2 = 11 residuo 0

11÷2 = 5 residuo 1

5÷2 = 2 residuo 1

2÷2 = 1 residuo 0

1÷2 = 0 residuo 1

Leyendo los residuos de abajo hacia arriba: 101101.

Respuesta: 4510 = 1011012
2. Convierte 0.625 a binario.¿Ver ejercicio resuelto?

0.625 × 2 = 1.25 → bit 1, queda 0.25

0.25 × 2 = 0.5 → bit 0, queda 0.5

0.5 × 2 = 1.0 → bit 1, queda 0 → termina.

0.625 = 5/8 y 8 es potencia de 2, por eso la representación es finita.

Respuesta: 0.62510 = 0.1012
3. ¿Por qué 0.1 no se puede representar exactamente en binario?¿Ver ejercicio resuelto?

0.1 × 2 = 0.2 → 0

0.2 × 2 = 0.4 → 0

0.4 × 2 = 0.8 → 0

0.8 × 2 = 1.6 → 1, queda 0.6

0.6 × 2 = 1.2 → 1, queda 0.2

En este punto reaparece 0.2 y el ciclo 0011 se repite indefinidamente.

Respuesta: 0.110 = 0.000112, periódico infinito; la máquina lo trunca.
4. Convierte 1101.0112 a decimal.¿Ver ejercicio resuelto?

Parte entera: 1·8 + 1·4 + 0·2 + 1·1 = 13

Parte fraccionaria: 0·(1/2) + 1·(1/4) + 1·(1/8) = 0.375

Se suman ambas partes.

Respuesta: 13.37510
