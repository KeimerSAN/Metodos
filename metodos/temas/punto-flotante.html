Aritmética de punto flotante

El álgebra de la máquina: por qué 0.1 + 0.2 no es 0.3 y cómo reescribir fórmulas para no perder cifras.

En esta página

Practicar este tema Ver los 16 temas

Idea central

La aritmética de punto flotante es la aritmética que realmente ejecuta el computador. No cumple todas las reglas del álgebra: la suma no es asociativa, restar dos números parecidos destruye cifras significativas y el resultado de cada operación se redondea al flotante más cercano antes de seguir.

El sistema de punto flotante se define por cuatro parámetros: la base β (2 en un computador), el número de dígitos de la mantisa t, y los límites del exponente. Solo existe un conjunto finito de números representables, y están distribuidos de forma desigual: muy juntos cerca de cero y muy separados cerca de los valores grandes.

Número de punto flotante

fl(x) = ± 0.d1d2…dt × βe

Cota del error relativo de redondeo

| (fl(x) − x) / x | ≤ ½ · β1−t = εm / 2

Epsilon de máquina (doble precisión)

εm = 2−52 ≈ 2.220446 × 10−16

El épsilon de máquina

Es el número positivo más pequeño tal que 1 + εm ≠ 1 dentro de la máquina. Marca el límite de precisión: ninguna tolerancia menor que εm tiene sentido, porque el computador no puede distinguir esa diferencia.

Formatoε de máquinaMenor normalMayor representable
Simple (32 bits)1.19 × 10−71.18 × 10−383.40 × 1038
Doble (64 bits)2.22 × 10−162.23 × 10−3081.80 × 10308

Las cuatro patologías de la aritmética finita

  1. Redondeo: cada operación devuelve el flotante más cercano al resultado exacto, no el resultado exacto.
  2. Cancelación catastrófica: al restar dos números casi iguales se pierden las cifras significativas coincidentes y el error relativo se dispara.
  3. Desbordamiento (overflow / underflow): superar el mayor representable da inf; bajar del menor da 0.
  4. Pérdida de asociatividad: (a + b) + c puede no ser igual a a + (b + c) cuando los órdenes de magnitud son muy distintos.

Ejercicio resuelto 1: el caso 0.1 + 0.2

En doble precisión, ni 0.1 ni 0.2 son exactos. Al sumarlos, los errores de representación se acumulan:

ExpresiónValor almacenado (17 cifras)¿Exacto?
0.10.10000000000000001No
0.20.20000000000000001No
0.1 + 0.20.30000000000000004No
0.30.29999999999999999No

Por eso 0.1 + 0.2 == 0.3 es False en Python, Java, C y JavaScript. La comparación correcta es abs((0.1+0.2) - 0.3) < 1e-9.

Ejercicio resuelto 2: cancelación catastrófica

Resolver x² − 10000x + 1 = 0 con la fórmula cuadrática usando aritmética de 8 cifras significativas.

El discriminante es √(10000² − 4) = 9999.9998. La raíz pequeña por la fórmula habitual queda:

MétodoOperaciónResultadoError relativo
Fórmula directa(10000 − 9999.9998) / 21.0000000 × 10−4≈ 10−4 (malo)
Fórmula racionalizada2 / (10000 + 9999.9998)1.0000000 × 10−4≈ 10−9 (bueno)

La resta 10000 − 9999.9998 cancela siete cifras coincidentes. Multiplicando arriba y abajo por el conjugado se evita la resta y se conserva la precisión.

Regla práctica: siempre que sea posible, reescribe la fórmula para evitar restar cantidades casi iguales.

Comprobarlo tú mismo en Python
import sys

print(0.1 + 0.2)                  # 0.30000000000000004
print(0.1 + 0.2 == 0.3)           # False
print(sys.float_info.epsilon)     # 2.220446049250313e-16

# Comparacion correcta: contra una tolerancia
tol = 1e-9
print(abs((0.1 + 0.2) - 0.3) < tol)   # True

# Perdida de asociatividad
a, b, c = 1e16, -1e16, 1.0
print((a + b) + c)   # 1.0
print(a + (b + c))   # 0.0

Errores comunes

  • Comparar flotantes con ==. Casi nunca es cierto. Se compara siempre abs(a - b) < tol.
  • Pedir una tolerancia menor que el épsilon de máquina. Un bucle con tol = 1e-20 en doble precisión nunca termina: esa diferencia no es representable.
  • Sumar una lista de mayor a menor. Sumar primero los términos pequeños conserva más precisión; sumar de mayor a menor los «absorbe».

Banco de ejercicios propuestos

Trabaja con aritmética de pocas cifras para ver el efecto amplificado.

1. Con aritmética de 4 cifras significativas y redondeo, calcula (1000 + 0.4) − 1000.¿Ver ejercicio resuelto?

1000 + 0.4 = 1000.4, que redondeado a 4 cifras significativas es 1000.

Luego 1000 − 1000 = 0.

El resultado exacto era 0.4: el sumando pequeño fue completamente absorbido.

Respuesta: 0 en lugar de 0.4 — error relativo del 100 %.
2. Reescribe f(x) = √(x² + 1) − x para evitar cancelación cuando x es grande.¿Ver ejercicio resuelto?

Cuando x es grande, √(x²+1) ≈ x y la resta cancela cifras.

Se multiplica y divide por el conjugado √(x²+1) + x.

Numerador: (x²+1) − x² = 1.

Respuesta: f(x) = 1 / (√(x² + 1) + x), numéricamente estable para todo x > 0.
3. ¿Cuántas cifras decimales garantiza la doble precisión?¿Ver ejercicio resuelto?

La mantisa tiene 52 bits explícitos más el bit implícito: 53 bits.

53 × log₁₀(2) ≈ 53 × 0.30103 ≈ 15.95.

Respuesta: Entre 15 y 16 cifras decimales significativas.
4. ¿Por qué conviene sumar de menor a mayor una lista de números positivos?¿Ver ejercicio resuelto?

Si se suma de mayor a menor, el acumulador crece pronto y los términos pequeños caen por debajo del épsilon relativo del acumulador.

Sumando de menor a mayor, los términos pequeños se agrupan entre sí antes de encontrarse con los grandes.

El algoritmo de Kahan (suma compensada) lleva esta idea más lejos guardando el error de cada paso.

Respuesta: Porque reduce la absorción de los sumandos pequeños y baja el error de redondeo acumulado.
